# rtu-atmo-audio-record

## Назначение

Скачивание аудио-записей разговоров КЦ РТУ (система «Атмосфера», стенд `rtu-cc-01.mos.ru`) по номеру обращения `conversationId`. Результат — mp3-файлы в папке `artifact/` проекта.

## Когда использовать

- «скачай запись разговора по обращению 188»
- «достань аудио звонка conversationId 189»
- «выгрузи записи разговоров за прошлую неделю»
- «получи аудиофайл обращения для расшифровки» (связка с навыком транскрибации)

## Предварительные условия

- [ ] Файл `.env` в корне проекта (или передан через `--env`), формат **JSON**:

```json
{
    "baseUrl": "https://rtu-cc-01.mos.ru",
    "user_login": "<логин>",
    "user_pass": "<пароль>"
}
```

- [ ] Сетевой доступ до `baseUrl` (стенд внутренний).
- Python 3 без внешних зависимостей (только стандартная библиотека).

## Пошаговый рабочий процесс

1. **Проверить `.env`** — если в корне проекта нет файла, уточнить у пользователя путь к нему. Не выдумывать креды.
2. **Скачать записи** готовым скриптом (в нём реализована вся цепочка: авторизация → список записей → скачивание):

```bash
python "<путь к навыку>/scripts/get_audio_record.py" <conversationId> [<conversationId> ...] [--out artifact]
```

Скрипт печатает пути сохранённых файлов. Выходные файлы именуются `<conversationId>_<fileName>.mp3`.

3. **Если conversationId неизвестен** — сначала получить список обращений и их номера (см. references/api-notes.md, раздел «Поиск обращений»), затем вернуться к шагу 2.
4. **Для выгрузки за период** — получить список записей через `GET /api/CallRecords` (обязательные `startDate`/`endDate`; `ownerId` = conversationId), затем скачать каждую по `conversationId`.

## Критические особенности стенда

Эти пункты проверены на живом стенде — не переоткрывать заново:

- Поле `link` в ответах содержит внутренний адрес `https://127.0.0.1:8340/...` — нерабочий. Использовать `fileName` + `relativePath` и подставлять `baseUrl`.
- `GET /api/ConversationProcessing/call-record` падает с HTTP 500 (серверный баг AutoMapper). Не использовать.
- `GET /api/CallRecords` требует `startDate` и `endDate`, иначе HTTP 400.
- Сертификат стенда не проходит проверку — скрипт отключает верификацию (`CERT_NONE`), для curl нужен `-k`.
- Скачанный файл — валидный MP3 (MPEG layer III, 64 kbps, 8 kHz).

## Обработка ошибок

| Симптом | Причина | Решение |
|---------|---------|---------|
| `Не найден .env` | файла нет в проекте | Запросить путь/креды у пользователя |
| HTTP 401 | токен истёк или неверный логин/пароль | Перезапустить скрипт (авторизация внутри); проверить креды |
| `[conv N] записей нет` | у обращения нет записи (не голосовой канал) | Сообщить пользователю; проверить канал обращения |
| HTTP 500 на call-record-list | сбой стенда | Повторить позже, сообщить пользователю |

## Контрольный список

- [ ] Файлы сохранены в `artifact/`, корень проекта чистый
- [ ] В ответе пользователю — пути к файлам и размеры
